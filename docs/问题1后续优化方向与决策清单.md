## 2. 已确认口径

1. I、II、III级巡检点分别展开为3、2、1个独立任务，所有任务必须完成。
2. 不同无人机同时到达同一点，分别计为一次巡检。
3. 同一无人机在原地延长停留仍只计一次；再次巡检同一点前必须先离开，因此同一路线不能连续出现相同 `Point_ID`。
4. 每次巡检耗时300 s；飞行时间逐段向上取整到整数秒；单机总时间不超过32400 s。
5. penalty丢弃任务只允许作为搜索中间状态，正式方案必须满足 `served == M`。
6. 允许使用OR-Tools Routing、OR-Tools CP-SAT或PuLP/MILP；CP-SAT/MILP只验证Case1=3架和Case3=4架。
7. 两个紧档各给最多30 min总计算时间，多起点运行并保存检查点。
8. 求解超时、部分覆盖或 `UNKNOWN` 不能写成数学不可行。

## 3. 代码任务

### 3.1 导入并复核现有成果

先收集并导入以下材料：

- 问题1求解代码；
- 四个Case的路线JSON；
- 独立校验报告；
- `result1.xlsx`；
- 运行参数、随机种子和求解状态。

对每个路线JSON独立复算任务覆盖、路线时间和最优性状态。Case3曾出现8.0839 h和8.1489 h两组结果，应优先核验8.0839 h对应路线；最终采用全部通过校验的历史方案中 \(T_{\max}\) 最小者，不能直接采用最后一次运行结果。

### 3.2 搜索Case1=3架、Case3=4架

每个紧档最多运行30 min，建议按以下流程实现：

1. 用当前4架或5架路线合并、压缩，生成3架或4架热启动；
2. 多起点运行极角扫描、容量感知聚类和任务级最近邻；
3. 使用2-opt、`relocate`、`swap`、最长路线任务移除—重插入和破坏—修复；
4. 针对同一点的多个任务副本设计专门移动，避免相邻出现相同 `Point_ID`；
5. 同时运行CP-SAT或MILP可行性模型，加入任务唯一分配、流量守恒、基地闭合、同点禁排、子回路消除和32400 s时限；
6. 每次得到更好方案立即写入检查点，并由独立校验器复算。

中间方案按以下顺序比较：

\[
(\text{未完成任务数},\ T_{\max},\ \sum_k T_k).
\]

第一项只有等于0时才是原问题的可行方案。

### 3.3 压缩当前可行方案的 \(T_{\max}\)

对四个Case中已经验证的最好路线继续运行2-opt、跨路线 `relocate`、`swap` 和破坏—修复。固定无人机数后按

\[
(T_{\max},\ \sum_kT_k)
\]

比较方案。任何新方案只有通过完整校验后才能替换当前基线。

## 4. 独立校验标准

每个正式方案必须同时满足：

1. 各巡检点完成次数严格等于等级要求；
2. `served == M`，任务不遗漏、不重复；
3. 每条路线从基地出发并返回基地；
4. 同一路线不存在相邻的相同 `Point_ID`；
5. 每次巡检计300 s，飞行时间逐段向上取整到秒；
6. 每架无人机总时间不超过32400 s；
7. JSON、校验报告和Excel中的路线及时间完全一致；
8. 自定义随机算法固定随机种子，保存运行参数和求解状态。

最优性状态统一填写：

- 下界与可行无人机数相等：`PROVEN_BY_LOWER_BOUND`；
- 只有可行上界、尚未证明最少：`BEST_FEASIBLE_NOT_PROVEN`；
- 精确模型超时或返回 `UNKNOWN`：保留当前状态，不标记不可行。
