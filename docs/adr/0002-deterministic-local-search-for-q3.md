# 问题3 采用确定性局部搜索而非 OR-Tools Routing

问题3 的航段通行时间取决于出发时刻（时变禁飞区，见 `docs/问题3.md` §5），OR-Tools Routing 基于静态弧代价，无法表达这种动态代价；且 Q1 已确认其局部搜索不暴露 seed 接口，复现只能依赖解档案。我们决定问题3 上层求解改为手写确定性多起点局部搜索（seed 派生、逐位可复现），几何内核为纯 numpy 闭式计算（线段-圆相交、切线-圆弧绕飞、可见图 Dijkstra），不引入 OR-Tools、shapely 与 SA 接受准则。决策过程与全部 12 项决策记录见 `Q3/PLAN.md` §1。

## Considered Options

- **OR-Tools Routing（弃用）**：Q1/Q2 的成功求解核心，但对问题3 失效——GLS 邻域评估假定弧代价可预计算且不随时刻变化；问题3 中同一航段的通行时间依赖出发时刻，且每次任务顺序调整后必须从首个受影响任务重算后续全部时间（`docs/问题3.md` §8.2.4），求解器内部无法接入这种"禁飞区感知"的动态重算。另 Q1 已付出代价：OR-Tools 无 seed 接口，复现只能以解档案为锚点（见 ADR-0001）。
- **自写确定性局部搜索（采纳）**：邻域算子（2-opt / relocate / swap / 块搬移 / 破坏-修复）直接作用于 task_routes，每次候选调用下层 `earliest_safe_travel` / `earliest_safe_service_completion` 全量重算受影响路线，天然满足"最早可行时间表"与词典序接受。全部随机性经 `hash((seed, case, stage, i))` 派生子种子，任意机器逐位复现，复现性强于 Q1。
- **shapely（弃用）**：math 环境未安装；且禁飞约束的时间判定（相交区间 ∩ 生效区间）无论是否用几何库都须手写，引入依赖收益有限，违反比赛"依赖最小化"原则。
- **SA 接受准则（弃用）**：词典序五元组 (S_max, Δ, ΣS_k, W, L) 上定义接受概率会复杂化实现；v1 以正确性优先，只接受严格词典序改进，SA 列为后续方向。

## Consequences

- **复现策略升级**：问题3 承诺"重跑求解得到相同方案"（seed=42 派生），不同于 Q1 的"档案锚点复算"策略；两者均由独立校验器（`verify.py` / `solve_q1.py --verify`）兜底。
- **解为启发式解**：不宣称 S_max、Δ 全局最优；热启动来自 Q2 strict 档案（经 sha256 契约校验），保证结果词典序不劣于问题2 路线的重估基线。
- **最优性让位于正确性的两处取舍**：可见图障碍集取"通行窗口内任一时刻生效的圆盘"（保守上界，多绕不多漏）；等待时长只枚举禁飞区事件边界而非连续优化。两者均记入 `Q3/PLAN.md` §13，留作 v2 改进点。
- **求解瓶颈转移**：下层可见图规模 O(n²)（n≤8）非瓶颈；算力主要消耗在上层候选的时间表重算，已用"受影响路线全量重算 + 未受影响路线缓存"控制。

## M5 运行结论（2026-08-17）

四 Case 在 seed=42、30 分钟/Case 预算下全部求解并发布，独立校验 9 项检查全过（`docs/问题3.md` §12）：Case1 复用、Case4 显著改进（Δ 3516→49，等待 20589→195）、Case2/Case3 因 Q2 热启动在禁飞约束下不可行而回退 greedy 基线且 30 分钟内未改进（字典序持平，不劣化）。

**补充决策——result3.xlsx 的点级验证口径**：提交工作表只含 Point_ID，不含任务展开信息；同一 UAV 访问同一点多次时，各展开任务可被邻域算子任意重排（Case1 曾出现同点任务逆序），因此"按 canonical 展开顺序还原任务序列"的强假设会产生假违规。校验器改为点级等价比较（每架 UAV 的 Point_ID 序列逐位一致 + 点出现次数 ≤ 展开任务数），任务级强校验由逐航段时间表承担。
