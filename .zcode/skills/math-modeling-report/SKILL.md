# 数学建模问题报告

把一道赛题的工作结果写成正式问题报告，输出到 `docs/问题X（n）报告.md`，按六段式组织。**核心约束是自包含**：成品报告必须独立可读，读者无需查阅任何其他文件即可理解全部内容。所有口径数值、术语定义、建模抉择依据都要内联写进报告正文，不得出现"见 XX 文档""与 Q1/Q2 对齐""遵循 CONTEXT.md""见 ADR 000X"等外部引用。

创作过程中**可以**读 `docs/赛题结构化拆解.md`、`Qx/` 代码与 `CONTEXT.md`、`docs/adr/`、`docs/问题X（n）.md`、`output/` 作为信息源——但取出的信息要写进报告本身，而非以引用形式留在成品里。读得到 ≠ 引用得到。

## Markdown 格式规范

报告采用标准 Markdown 格式（CommonMark + 数学公式扩展）。不使用 Obsidian 特有语法。

### 数学公式（必须）

- **块级公式**：必须用 `$$…$$` 包围，独占一行/多行，不得使用 `\displaystyle` 硬凑行内
- **行内公式**：用 `$…$` 包围
- 约束条件编号用 `\tag{…}` 或行末 `\qquad (n)`

```markdown
功率平衡约束：
$$
P_t^{pv} + P_t^{wt} + P_t^{grid} + P_t^{dis} = L_t + P_t^{ch} \qquad \forall t \in T
$$

单位供电成本定义为 $C_{unit} = \frac{C_{total}}{\sum_t L_t}$。
```

### 关键信息块（必须）

用标准 Markdown 引用块 + 加粗标题标记关键信息，替代 Obsidian callout。以下类型为推荐用法：

| 引用块标题 | 用途 | 示例场景 |
|-----------|------|---------|
| `> **重要**` | 核心假设、关键约束 | 模型假设摘要、不可违反的硬约束 |
| `> **注意**` | 注意事项、局限性 | 适用边界、假设敏感项 |
| `> **结论**` | 关键结论、最佳结果 | 最优方案数值、对比结论 |
| `> **说明**` | 补充说明、参数注释 | 参数取值依据、口径定义 |
| `> **待验证**` | 待验证项、开放问题 | 敏感性待测参数、模型扩展方向 |
| `> **示例**` | 计算示例、案例演示 | 典型场景演算、公式代入示例 |
| `> **要点**` | 建模技巧、方法要点 | 为何选择此方法、算法优化点 |

折叠内容用 HTML details 标签：
```markdown
<details>
<summary>详细推导（点击展开）</summary>

此处为完整推导过程……

</details>
```

### 强调（推荐）

关键数值和结论用 `**text**` 加粗强调：
```markdown
联合运营方案的单位供电成本为 **0.487 元/kWh**，较独立运营降低 **12.3%**。
```

### 图片

用标准 Markdown 语法引用图片：
```markdown
![图题](路径)
```

## 执行步骤

1. **定位本题材料**
   - 读 `docs/赛题结构化拆解.md` 取本题显性任务、已知参数、硬约束、难点
   - 读对应题号目录 `Qx/`：代码、`CONTEXT.md`、`docs/adr/`、`output/`，取实际数值结果与建模抉择理由
   - 读 `docs/问题X（n）.md`（若存在）取已有分析
   - 完成：能列出"任务 + 参数 + 已得数值 + 抉择理由"四栏，每栏非空

2. **写入标题**
   - 报告以一级标题 `# 问题X（n）报告` 开头
   - 标题下方注明日期（如 `> 成文日期：YYYY-MM-DD`）

3. **按六段式落稿**
   - 标题严格用 `## 一、问题分析` … `## 六、结论`（中文序号 + 顿号，区别于工作文档的 `## 1.`）
   - 依下文 §段落规格 逐段填写，各段的关键信息块按推荐类型使用
   - 数学公式严格用 `$$…$$`（块级）和 `$…$`（行内）
   - 完成：六段标题齐全，每段满足其"必须包含"清单

4. **内联化**
   - 把 §口径清单 的数值写进报告的 §模型假设 或 §参数取值表，作为本报告自含参数，不标注"来自其他文档"
   - 建模抉择类假设（充电计价、SOC 边界、投资折算、典型日 ×365）在假设条目内直接写明依据：来源（题目明示 / 工程惯例 / 建模抉择）+ 一句理由，不指向 ADR 编号
   - 术语在报告内首次出现处给出定义，或集中列一节术语表
   - 完成：报告内任何口径、术语、抉择都能在本文内查到完整说明

5. **数值核对**
   - 报告每个数值与代码输出或 `CONTEXT.md` 逐一对齐，统一 3 位小数
   - 完成：零数值不一致

6. **自包含校验**
   - 报告不得出现指向**本仓库其他文件**的引用。检索以下痕迹，命中即缺陷，改写为内联表述：
     - 仓库路径：`docs/`、`CONTEXT.md`、`adr/`、`output/`、`赛题结构化拆解`、`Q1/`、`Q2/`
     - 外指话术：`见 …文档`、`见 …文件`、`参见 …`、`详见 …`、`与 …对齐`、`遵循 …`、`同 …口径`（省略号指本仓库其他文件/文档时）
     - ADR 编号：`ADR 000`、`0001`、`0002`、`0003`…
   - 指向**报告自身**的引用允许：如"见下表""详见 §三""同口径对比"（指本文内的对比）不视为缺陷
   - 完成：外指痕迹在正文（含表格、公式、注释、checkbox）中零命中

7. **格式校验**
   - 数学公式全部用 `$$…$$`（块级）/ `$…$`（行内），无裸 LaTeX 命令
   - 关键信息块用 `> **标题**` 格式，无 `> [!type]` 残留
   - 完成：上述检查项全部通过

8. **落盘**
   - 写到 `docs/问题X（n）报告.md`
   - 完成：文件写入，一级标题与六段标题在文件中各出现一次

## 段落规格

### 一、问题分析
必须包含：
- 显性任务（要算什么、输出哪些指标）
- 与前后题的口径差异（独立 vs 联合、典型日 vs 全年、固定 vs 分时电价）——差异须在本报告内讲清，不靠读者去翻其他题报告
- 输入数据来源（附件几 + 本题目录），写明即可，不要求读者打开

推荐信息块：
```markdown
> **说明**：与本问题其他子题的差异
>
> 本题与问题 X(1) 的核心差异在于……
```

### 二、模型假设
必须包含：
- 编号假设清单，集中列出，不散落在各节
- 每条标注依据来源：题目明示 / 工程惯例 / 建模抉择；抉择类须附一句理由，理由内联写明，不指向 ADR

推荐信息块——在假设清单前加关键假设摘要：
```markdown
> **重要**：核心假设
>
> - 购电成本：光伏 **0.4**、风电 **0.5**、电网 **1.0** 元/kWh
> - 储能充放电效率 **0.95**，SOC 范围 **10%～90%**
> - 典型日 × 365 估算全年
```

### 三、模型建立
必须包含：
- 集合与时段定义
- 决策变量表（符号 | 含义 | 单位）
- 约束条件（逐条编号，LaTeX，块级公式用 `$$…$$`）
- 目标函数（LaTeX，块级公式用 `$$…$$`）
- 参数取值表（口径数值全部落表，作为本报告自含参数）

推荐信息块——参数取值表前加参数来源说明：
```markdown
> **说明**：参数取值依据
>
> 购电价格取自题目给定水平，储能单价取自行业均价参考……
```

### 四、结果与分析
必须包含：
- 结果汇总表（方案 | 指标 | 数值）
- 同口径对比（独立 vs 联合、有无储能）——对比所需数值须全部出现在本报告内
- 机理分析：为什么是这个结果，不只报数字

推荐信息块：
```markdown
> **结论**：关键发现
>
> 联合运营方案的单位供电成本为 **0.487 元/kWh**，较独立运营降低 **12.3%**。
> 降幅主要来自园区间互济减少了 **15%** 的电网购电。

> **注意**
>
> 上述结论建立在储能投资 10 年线性年化的基础上。若储能成本上升 20%，联合运营优势将缩窄至 5% 以内。
```

### 五、模型检验
必须包含：
- 功率平衡残差 < 1e-4
- 约束满足校验（SOC 区间、充放互斥、变量非负）
- 敏感性分析（至少一个关键参数）
- 检查项 checkbox 清单（`- [ ]` / `- [x]`）

推荐信息块：
```markdown
> **待验证**
>
> - 储能投资成本 ±30% 敏感性
> - 分时电价场景扩展
```

### 六、结论
必须包含：
- 一段话数值结论
- 适用边界：哪些假设变化会推翻结论

推荐信息块：
```markdown
> **结论**：数值结论
>
> 联合运营 + 储能配置 XX kW / XX kWh 方案下，单位供电成本为 **XX 元/kWh**，
> 全年总成本为 **XX 万元**。

> **注意**：适用边界
>
> 以下假设若发生变化，结论可能被推翻：
> - ……
```

## 口径清单

以下口径须在报告正文（§模型假设 或 §参数取值表）内联写明，作为本报告自含参数，不标注"来自其他文档"：

- 购电成本：光伏 0.4、风电 0.5、电网 1.0 元/kWh
- 储能：充放电效率 0.95、SOC 10%~90%、功率 800 元/kW、容量 1800 元/kWh、寿命 10 年
- 不向电网售电；弃电不计成本；消纳计成本（储能充电属消纳，须在假设条目内直接写明理由）
- 典型日 × 365 估算全年
- 单位供电成本分母 = 实际负荷电量（非发电量、非购电量）
- 联合运营：先聚合后平衡，不计园区间损耗与结算
- 投资线性年化、不贴现、无残值（题目未给贴现率）
- 风光优先消纳、不足才网购

## 术语表

报告内统一使用以下词，首次出现处给出定义（若另立术语表小节则集中列出），不指向 `CONTEXT.md`：

- 联合运营 / 独立运营
- 园区间互济
- 风光消纳 / 弃风弃光 / 风光消纳率
- 单位供电成本
- 储能 SOC、充放电互斥

## 写作风格

### Markdown 格式规范

- **标题**：报告以 `# 问题X（n）报告` 开头，日期紧跟标题下方
- **数学公式**：
  - 块级公式必须用 `$$…$$` 包围，独占行，不得用 `\displaystyle` 在行内硬凑
  - 行内公式用 `$…$` 包围
  - 约束条件编号用 `\tag{…}` 或行末 `\qquad (n)`
  - 公式内如需换行，用 `\begin{aligned}` 等环境包裹在 `$$…$$` 内
- **关键信息块**：用标准 Markdown 引用块 + 加粗标题：
  - 格式：`> **标题**`，标题可选 `：副标题`
  - 引用块内可嵌套标准 Markdown（列表、代码块、公式等）
  - 折叠内容用 `<details>` / `<summary>` HTML 标签
- **强调**：关键数值和结论用 `**text**` 加粗

### 通用规范

- **表格**：Markdown 表格，列对齐用 `|:---|`（左）/ `|---:|`（右）/ `|:---:|`（居中）
- **数值**：统一 3 位小数
- **em dash**：用 U+2014（—）；Edit 匹配失败时按行号替换或用 PowerShell `[char]0x2014` 构造
- **配图**：`savefig` 写出图片文件，报告中用 `![图题](路径)` 引用；不用 `plt.show`
- **章节引用**：指向报告自身的引用用 `§段落名` 格式（如 `详见 §三`），不写"见上文""见下文"

### 格式检查清单

落盘前逐项确认：
- [ ] 报告以 `# 问题X（n）报告` 一级标题开头，日期紧跟其后
- [ ] 所有块级公式用 `$$…$$`，无裸 `\[…\]` 或 `\displaystyle`
- [ ] 所有行内公式用 `$…$`
- [ ] 至少 3 处关键信息块（`> **标题**`），类型不重复
- [ ] 关键数值用 `**…**` 加粗强调（至少 3 处）
